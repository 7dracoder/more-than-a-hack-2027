# BlindSpot v0.4 experiment log

Generated by `python scripts/run_v04_experiments.py`. Aggregate public-window scores only.

## How to run

**Colab (recommended):** open `notebooks/BlindSpot_v04_Colab.ipynb` in Colab (File → Upload notebook),
keep the default CPU runtime, choose Runtime → Run all, and upload
`data/drive-transfer/BlindSpot_v04_project.zip` when the file picker appears. If the source changes,
run `python scripts/build_v04_colab.py` again, then use the new notebook and ZIP together, because
the notebook checks the ZIP's checksum.

**Local:**

```powershell
pip install -r requirements-v3.txt
python scripts/run_v04_experiments.py                 # all groups, ~10-15 min on CPU
python scripts/run_v04_experiments.py contacts shape  # only some groups
python scripts/run_v04_experiments.py --candidate all # export CoreOrigin.csv for the chosen group
python evaluation/validate_submission.py data/experiments/blindspot-v04/all/candidate/CoreOrigin.csv
```

The first run reads the raw tracking once (a few minutes) and caches it under
`data/experiments/cache/` (git-ignored). Later runs reuse the cache.

## What is being tested

New features live in `possession/event_features.py`. Each is added on top of the v0.3.1 set:

| Group | Features | Why |
|---|---|---|
| `baseline` | v0.3.1 only (68) | Reference. Must reproduce whole-run 0.4457 / fixed-time 0.6200 |
| `contacts` | team of last/next close approach (1 m, 2 m), time since/until | Public labels change owner around contacts; bridges ball gaps |
| `asym` | past-only vs future-only contact and control windows | Lets the model locate *when* the owner changes, not just who |
| `gap_out` | ball-gap length, out-of-pitch distance now/last seen/next seen, time since/until out | Dead balls start when the ball leaves the pitch |
| `ballmotion` | placed-ball duration, time since/until ball moves | Restarts begin from a still ball |
| `shape` | team spread, width, forward position and velocity, pressure counts | Work when the ball is missing (41% of graded frames) |
| `all` | everything above | |

## How to read the results

* Every score comes from models that did not see the labels of the fold being scored
  (whole-run purged folds and equal-duration folds, both with a 300-frame embargo).
* If `baseline` does not reproduce 0.4457 / 0.6200, the harness is broken; stop and report it.
* Only 17 public possessions exist. The conservative development selection rule requires a spell-F1 gain greater than 0.06 in both protocols; this is a heuristic, not a statistical significance threshold.
* The exported candidate is fitted on all public labels. Its public score is training fit,
  not validation.

## Evaluation scope

These experiments reuse the previously inspected public sample. Choosing among seven groups on this same sample introduces selection bias; cross-fitting does not make the selected result independent validation. The new features may use last/next observations across a whole half, including shared unlabelled raw context across folds. The 300-frame embargo excludes training labels, not all overlapping raw evidence.

The runner saves per-fold prediction CSVs, score details, masks, source/input hashes and completed-group checkpoints under `data/experiments/blindspot-v04/`. Baseline scores must match the frozen reference before other groups run. Where the local reference CSVs are available, every baseline fold must also match byte-for-byte.

## v0.5 structural experiments (22 October 2026)

Three groups were declared and their constants fixed in `possession/structure.py` before scoring.
None of them was tuned afterwards.

| Group | What it does |
|---|---|
| `contacts_team_only` | Baseline model decides live/dead; contacts model decides H vs A |
| `baseline_outplay` | Baseline plus an out-of-play rule: ball observed more than 1 m beyond a line is dead, and the stoppage holds (soft) until the ball is next seen inside and kicked at more than 5 m/s, capped at 60 s |
| `team_only_outplay` | `contacts_team_only` plus the out-of-play rule |
| `team_only_outplay_snap` | The above, plus each H/A change moved to the nearest new-team contact within 1 s |

Research basis: IFAB Law 9 (ball out when it wholly crosses a line); the possession-zone and
contact rules of [Vidal-Codina et al. 2022](https://arxiv.org/abs/2202.00804) (gain needs a change of
ball direction or speed near the player). Before scoring, out-of-pitch frames were checked against
the labels: 92 of 92 public frames more than 1 m outside are D. Content was rephrased for
compliance with licensing restrictions.

| Group | Whole-run spellF1 | Fixed-time spellF1 | Wrong-team frames (W / F) | Dead called live (W / F) | Live called dead (W / F) | Changes within 1 s (W / F) |
|---|---:|---:|---:|---:|---:|---:|
| baseline | 0.4457 | 0.6200 | 782 / 681 | 589 / 747 | 310 / 238 | 4 / 7 |
| contacts_team_only | 0.5000 | 0.6341 | 512 / 447 | 589 / 747 | 310 / 238 | 4 / 8 |
| baseline_outplay | 0.4571 | 0.6200 | 745 / 649 | 496 / 654 | 312 / 240 | 5 / 8 |
| **team_only_outplay** | **0.5111** | **0.6341** | **512 / 447** | **496 / 654** | 312 / 240 | **5 / 9** |
| team_only_outplay_snap | 0.5111 | 0.6244 | 506 / 455 | 496 / 654 | 312 / 240 | 5 / 8 |

Reading:

* `team_only_outplay` reduces wrong frames by about 20% under **both** protocols
  (1,681 to 1,320 whole-run; 1,666 to 1,341 fixed-time), with no category getting worse beyond
  2 frames. Its spellF1 gain is +0.065 whole-run but only +0.014 fixed-time, so it does **not**
  pass the 0.06-in-both-protocols rule. The selection script therefore still picks `baseline`.
* Contact snapping does not help; drop it.
* The remaining spellF1 losses are mostly short possessions under 3 s that are missed entirely
  (5 of 17 public possessions), and long stoppages with the ball inside the pitch (fouls, a
  goal-kick restart where the ball was carried back into play). The out-of-play rule cannot see
  those.
